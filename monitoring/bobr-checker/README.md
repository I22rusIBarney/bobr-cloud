# Bobr Cloud Checker

Центральный мониторинг VPN-локаций BobrGO на отдельном VPS. Установка Docker Compose, публичный HTTPS через Caddy и автоматические TLS-сертификаты Let's Encrypt.

## Требования

- Ubuntu или Debian, архитектура x86_64/ARM64
- Домен с DNS A-записью на публичный IPv4 этого VPS
- Доступные извне TCP 80 и TCP 443; UDP 443 рекомендуется для HTTP/3
- URL подписки, доступный с VPS

## Установка — два ввода

```bash
git clone -b feature/bobr-cloud-checker https://github.com/I22rusIBarney/bobr-cloud.git
cd bobr-cloud
sudo bash monitoring/bobr-checker/install.sh
```

Установщик попросит только:
1. Домен панели, например `monitor.example.com`
2. Ссылку подписки

Дальше он сам:
- установит Docker Engine и Docker Compose, если их нет;
- проверит, что DNS домена указывает на публичный IPv4 этого сервера;
- проверит доступность URL подписки;
- проверит, не заняты ли порты 80/443;
- если UFW уже активен — добавит правила TCP 80, TCP 443 и UDP 443;
- запустит Checker и Caddy;
- дождётся готовности Checker и проверит HTTPS локальным запросом к Caddy с проверкой доверия сертификату (без зависимости от Hairpin NAT);
- сгенерирует пароль администратора и покажет его в конце.

При повторном запуске установщик сначала проверит существующую установку, включит JSON-режим подписки и обновит образ Checker. Если Checker и HTTPS работают, он не будет переустанавливать сервис или запрашивать параметры заново, а сразу покажет сохранённые логин и пароль. Если проверка не пройдёт, выведет диагностические логи.

Откройте в панели хостера входящие TCP 80 и TCP 443 (UDP 443 — для HTTP/3), если у провайдера есть отдельный сетевой firewall. Установщик не включает UFW автоматически и не меняет внешний firewall провайдера: это защищает от случайной потери SSH-доступа.

После установки: `https://ВАШ-ДОМЕН`.

## Управление

```bash
bobr-checker status
bobr-checker logs
bobr-checker restart
bobr-checker update
bobr-checker config
```

Логи Caddy: `docker logs -f bobr-cloud-caddy`.

Конфигурация хранится в `/opt/bobr-checker/.env` (права 600). Сертификаты Caddy — в `/opt/bobr-checker/caddy_data`. При повторном запуске установщик создаёт резервную копию настроек, позволяет изменить домен и URL подписки, не сбрасывая пароль.

## Формат подписки

Для Remnawave по умолчанию включён `SUBSCRIPTION_JSON_FORMAT=true`: Checker запрашивает JSON в формате Happ и раскрывает узлы стандартных Xray balancers в отдельные проверки. Команда `bobr-checker update` также включает этот режим, обновляет Docker-образ и перезапускает сервис. Для обычных Base64/share-подписок можно вернуть `false` в `/opt/bobr-checker/.env`.

## Фильтры отображения

В панели добавлен раздел **«Фильтры»**:
- по умолчанию скрываются только заголовки групп AUTO-ВЫБОР / AUTO-SELECT; реальные узлы внутри этих групп остаются видимыми и продолжают проверяться;
- можно задать свои регулярные выражения для скрытия заголовков групп;
- можно отдельно скрывать карточки узлов по имени;
- настройки сохраняются в браузере (localStorage) и не меняют подписку, проверки или метрики.

При повторном запуске установщик синхронизирует шаблон панели из репозитория в `/opt/bobr-checker/custom` и перезапускает Checker.

## Безопасность

- Порт Checker 2112 не опубликован на хосте; доступ идёт через Caddy.
- Caddy автоматически получает и продлевает TLS-сертификат.
- Авторизация панели включена.
- Не публикуйте `.env`: в нём ссылка подписки и пароль.
